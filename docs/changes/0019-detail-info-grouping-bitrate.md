# 详情信息分组、轨道来源、码率与 chips 去重（阶段 2C）

状态：已执行。影响范围：`core/common` 码率格式化；`feature/detail` 信息表分组与文件信息浮层；相关单测；版本号。

## 背景

UI/UX 审计阶段 2C 修复四个问题：

- **F-25（P2）**：详情信息表 12 行无分组，文件属性与播放统计混杂。
- **F-06（P2）**：“音轨数量（导入探测）”“内嵌字幕轨（导入探测）”“未识别，以播放器为准”把两套数据源抛给用户。
- **F-07（P2）**：码率显示原始 bps（如 3205365 bps），未换算。
- **F-15（P2）**：首屏 chips（分辨率/时长/大小）与信息表重复同一数据。

## F-25 信息表分组

主表按 **文件 / 视频 / 音频 / 播放记录** 四组，组间 `SectionHeader` + 间距：

- 文件：文件名、大小、导入时间、文件状态；
- 视频：时长、分辨率、视频编码、码率；
- 音频：音频编码；
- 播放记录：最近播放、播放次数。

## F-06 轨道来源归位

主表移除“音轨数量（导入探测）”“内嵌字幕轨（导入探测）”两行；探测数据移入**文件信息浮层**，并新增“导入时探测”来源行（注明导入时间）。主表只保留可信展示，探测数据在文件信息中注明来源。

## F-07 码率格式化

新增 `formatBitrate(bps: Long?): String?`（core/common）：按 1000 进制 bps→Kbps→Mbps→Gbps，保留 1 位小数；null/<=0 返回 null，界面显示“未知”。例：3205365 → `3.2 Mbps`。单测覆盖边界（999/1000/3205365/1e9/null/0/负）。

## F-15 chips 去重

删除首屏 3 个重复 chips（分辨率/时长/大小，均已在信息表）；保留标题 + 观看进度行 + 播放按钮，首屏信息不重复。

## 已知限制

- 播放器未打开时无真实轨道数据，文件信息中探测值注明“导入时探测”来源；真实轨道以播放器为准的说明保留在探测行为 0 时的文案。
- 音频组当前仅音频编码（探测轨道数已移入文件信息）。
