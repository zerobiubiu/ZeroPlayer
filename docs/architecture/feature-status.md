# 功能完成度与遗留问题

状态：现状文档（每次阶段交付更新）

本表区分代码实现与实际验证；模拟器结果不能推断实体设备的硬件解码、蓝牙或听感。

## 一、文件树与页面

| 能力 | 当前实现 | 位置与边界 |
|---|---|---|
| 应用名称与 ABI | ZeroPlayer；仅 `arm64-v8a` | 保留 `com.privateplayer.media` 应用 ID，32 位 ARM 和无转译的 x86 不能安装 |
| 一级导航 | 首页、设置 | 视频详情和播放器为二级页面，Wi-Fi 控制为浮层 |
| 文件树 | 展示当前目录的文件与目录，支持进入和返回 | 首页与网页共用 `FileTreeRepository`；不扫描系统媒体库 |
| 文件操作 | 新建文件夹、重命名、移动、删除、导出、分享；首页行菜单与详情页更多菜单共用分组菜单（信息/传输/管理/危险）与同一套对话框 | 文件与非空文件夹操作同步内部视频记录；导出使用系统选择器，分享授予临时只读 URI；删除/移动/重命名命中播放会话时先停服 |
| 点击与详情 | 点击视频播放，长按菜单进入详情；详情页顶栏“更多”提供重命名/移动/删除/导出/分享 | 非视频保留在文件树，不假装可以播放；详情删除后自动返回，首页列表同步 |
| 旧逻辑归档 | 不再提供媒体库、收藏、播放列表入口 | 旧数据库记录和磁盘文件保留；旧 UUID 文件使用原名展示 |
| 设置 | 播放、字幕、手势、显示、导入、存储与关于；一级为分组入口，二级页只放该类型选项 | 枚举使用 `DropdownMenuItem`，数字通过输入框校验；列表入口显示当前摘要 |
| 设置保存模型 | 全部即时生效：开关点按即存，数值在键盘完成或失焦时写入，无逐行“保存”按钮 | 非法值不落库并恢复上次值；写入经串行队列保序，最后一次修改最后落盘；保存失败弹出 Snackbar |
| 文案与术语 | 用户可见文案全部模块资源化（中文），经 stringResource/Context.getString 引用；容器称“文件夹”、技术路径称“目录”；两个导入开关在设置页与 Wi-Fi 面板同源同名 | CopyResourceGateTest 门禁：硬编码白名单扫描 + 术语黑名单 + 同源断言；数据层错误原因文案待 2D 资源化 |
| 超大目录 | 暂未分页 | 单级目录会直接列举其子项 |

## 二、导入与 Wi-Fi 文件服务

| 能力 | 当前实现 | 位置与边界 |
|---|---|---|
| 本机选择 | SAF 多选、任意格式，选择后复制 | 正式文件位于 `files/media`，原文件只读 |
| 系统打开 | 注册 `ACTION_VIEW` 视频处理 | 先复制到私有目录，再以内部 ID 播放 |
| 系统分享导入 | `ACTION_SEND` / `ACTION_SEND_MULTIPLE` | 支持 `EXTRA_STREAM` 和 `ClipData`，不自动播放 |
| 大文件 | 文件复制、网页接收和导出均为流式 | 固定缓冲区，不整体读取视频；磁盘空间检查预留 256 MiB |
| 持久导入 | Room 任务 + WorkManager + 完成标记 | 进程终止后重新调度；未完成复制仍依赖来源授权 |
| 异常/取消/重试 | 任务展示、错误原因、取消和重试 | 临时授权丢失时要求重新选择；已接收网页文件失败后保留暂存 |
| 重复提示 | 大小与首段哈希用于疑似重复提示 | 不因疑似重复丢弃副本 |
| Wi-Fi 服务 | 手动启停，固定 8765 端口，地址为根路径；无鉴权风险独立警示块（图标+文字）紧邻启动按钮并常驻 | 网页静态资源随 APK 打包，浮层显示本次上传记录；服务本身不加鉴权 |
| 网页文件管理 | 任意格式上传、下载、目录创建、重命名、移动、删除 | 服务无令牌、无登录、HTTP 明文；能连接的设备均可读写文件 |
| 数据一致性 | 私有根路径限制、无覆盖改名提交、文件身份日志与补偿 | 面向进程中断；同文件系统改名不二次复制，不依赖硬链接 |
| 空间统计 | 按 1024 进制标注 KiB / MiB / GiB / TiB | 统计整个私有文件树，清缓存保留未完成任务和标记 |

## 三、播放器能力

| 能力 | 当前实现 | 验证重点 |
|---|---|---|
| 解码与渲染 | 真实 libmpv、FFmpeg 和 Surface | ARM 真机 MediaCodec、软解回退与不同编码 |
| 播放与暂停 | 同一引擎状态驱动 UI 和系统会话 | 页面、通知栏和外部控制器状态一致 |
| 进度控制 | 底部进度条；双击按设置步长跳转 | 文件首尾、暂停及无时长情况 |
| 横向手势 | 按滑动距离线性换算，并按手势峰值速度放大 1×～16× 档位；刻度 1/2/5/10/20 秒，无固定上限 | 真实设备震动、不同屏幕尺寸与无障碍；震动可在设置中关闭 |
| 长按倍速 | 异步控制，松手恢复；预置 libmpv `scaletempo2` | 真机画面流畅度、常速听感与功耗 |
| 音量与亮度 | 右侧上下滑音量、左侧上下滑亮度；音量键显示百分比 | 系统音量一致性及设备按键行为 |
| 字幕 | 轨道选择、延迟与样式；普通字幕默认在视频画面下侧；记住每个视频上次选择的字幕（含关闭） | 同目录字幕、旧字幕、ASS 自带排版及黑边布局 |
| 退出行为 | 返回关闭播放页即结束会话并释放引擎；按主页键退到桌面继续后台播放 | 通知栏/锁屏状态同步、返回后服务是否残留 |
| 音轨与画面 | 音轨选择、画面比例（顶栏比例图标打开比例面板）、横竖屏切换（顶栏独立旋转按钮，一次点击；“更多”不再保留第二入口） | 多音轨实际听音、Surface 重建 |
| 播放模式 | 同目录顺序播放、单个/目录循环、随机、自动下一文件 | 后台连续播放、删除/移动后处理 |
| 进度记忆 | 真实播放周期、暂停及暂停跳转、切源和服务释放时持久化 | 跳转不重复计数、进程中断与多入口顺序 |
| 面板语义 | 倍速/比例/音轨/字幕/模式仅当前项勾选+高亮；动作/导航/状态不显示勾选；读屏带单选语义 | 真机 TalkBack 播报、厂商差异 |
| 面板沉浸式 | 面板在自己的对话框窗口隐藏系统栏，打开/关闭/重开保持沉浸，退出播放页恢复 | 真机手势/三键导航、临时显示行为 |
| 播放队列 | “播放队列”面板渲染当前目录队列（仅文件名），当前项高亮带勾，点击条目经受控 API 跳转（无效/重复/连点为无操作）；打开自动定位当前项，限高滚动，空队列空状态；上一集/下一集与播放模式保留 | 大目录滚动性能、跳转与系统会话并发时序 |
| 文件操作保护 | 删除/移动/重命名命中当前播放媒体或活动队列时，先经停服路径结束会话再动文件；队列随会话销毁，重开按目录重建 | 真实设备引擎释放时序、停止等待上限兜底 |

## 四、Android 系统媒体会话

| 能力 | 当前实现 | 验证重点 |
|---|---|---|
| Media3 依赖 | Common / Session 1.11.1 | 不引入 ExoPlayer；Session 必需传递依赖含 datasource，但不启用网络播放 |
| 自定义 Player | `MpvMedia3Player : SimpleBasePlayer` | play/pause、seek、倍速、音量、真实快照与媒体 ID 对齐 |
| 媒体服务 | `PlayerMediaSessionService` + 单实例协调器 | 页面离开、Activity 重建、后台继续及服务销毁 |
| 系统入口 | 通知、系统媒体会话、外部 `MediaController`、媒体按键 | 实体蓝牙、锁屏 UI 与厂商系统需真机验证 |
| 媒体信息 | 已有标题、时长及封面 | 没有作者信息时不虚构，私有文件路径不对外发布 |
| 音频焦点与唤醒 | 媒体前台服务、音频焦点与播放时 CPU 唤醒 | Android 15+ 后台启动限制、音频焦点丢失/恢复 |
| 并发顺序 | 切源与外部命令共用同步门，按提交票据抑制旧请求 | 不允许旧媒体命令作用于新媒体；测试还需覆盖设备时序 |

## 五、数据与播放引擎

- Room 保留媒体元数据、播放历史、导入任务及旧逻辑归档表；DataStore 保存现有偏好。
- `PlaybackEngine` 是应用内接口；libmpv 是唯一实际播放/解码引擎。系统会话适配层不创建第二个解码器。
- JNI 入口、AndroidX 和 Android 系统共享库按平台加载；libmpv / FFmpeg 等第三方播放组件静态编入随包 `libplayer.so`，不需要另装播放库。
- 许可证、对应源码和重新链接材料仍须按实际分发方式审核；当前包体及 ABI 证据见 [ARM64 变更](../changes/0004-arm64-only.md)。

## 六、已知限制与后续验证

1. 尚无实体 ARM 设备证据；硬件解码、不同厂商 Surface 与 AudioTrack 行为、音质和触觉反馈均需真机回归。
2. 模拟器中使用 ARM64 转译运行，不等于实体 ARM 速度或真实蓝牙链路。
3. 音频变速滤镜常驻可避免切换时自动滤镜反复创建，但常速也需经过滤镜；真实音质和功耗需复核。
4. 网页服务是按要求无认证的临时 HTTP 服务；不可信网络中的其他设备可访问、修改及删除文件。
5. 系统回收复制中的临时 URI 授权后必须重新选择来源；网页传输中断未完整接收的文件需要重新上传。
6. 文件树无分页，极大目录的启动及滚动性能尚需专项评估。
7. 已按 GPL-3.0-only 开源并提供第三方声明与重新链接材料说明（见 [开源发布变更](../changes/0007-open-source-release.md)）；静态链接 LGPL 组件的实际履约仍由分发者按 [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md) 审核。

本轮执行命令、实际结果与残余限制分别记录于 [文件树与传输变更](../changes/0005-file-tree-transfer.md)、[Media3 会话变更](../changes/0006-media3-session.md) 与 [开源发布变更](../changes/0007-open-source-release.md)。
