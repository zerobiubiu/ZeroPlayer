# 私有文件树与导入

状态：现状文档  
影响范围：`core:storage`、`data`、首页、Wi-Fi 服务、系统打开与分享

## 1. 目录布局

```text
files/
  media/                   首页和网页共用的文件树：视频、字幕与其他文件
  subtitles/<mediaId>/     详情页单独导入的字幕副本及旧版字幕
  import-staging/          本机选择/分享文件的持久暂存及完成标记
  import-commits/           导入目标与 dev/ino 文件身份日志
  web-uploads/             网页接收的暂存文件与接收日志
  backups/.file-tree-operations/  文件操作恢复日志
cache/
  thumbnails/              缩略图缓存
  temporary/               旧版导入暂存；受保护的未完成任务不清理
  image_cache/             Coil 缓存
```

`media` 表的 `relativePath` 相对于 `filesDir`；文件树接口的路径相对于 `files/media`，空字符串表示根目录。用户只在首页和网页操作该树，应用不申请媒体库读取权限，也不扫描系统媒体库或外部目录。

历史版本的逻辑文件夹和播放列表记录留在数据库内，不再成为界面概念；原视频没有被自动移动。旧网页上传可能以 UUID 命名磁盘文件，列表显示原始名称，但操作和持久路径仍指向原文件。用户主动重命名时才改变磁盘名称。

## 2. 本机和系统分享导入

1. 首页「+」使用 Storage Access Framework 选择一个或多个文件；系统 `ACTION_VIEW`、`ACTION_SEND`、`ACTION_SEND_MULTIPLE` 接收来源 URI。
2. 读取文件名、可用大小和 MIME；保留读授权，写入 Room `import_tasks` 并调度 WorkManager。目标文件名冲突时采用不覆盖的名称。
3. 通过 1 MiB 缓冲流式复制到 `files/import-staging`，周期性同步文件并保存字节进度。复制结束、大小校验及数据同步后写入完成标记。
4. 在共享文件树锁内确认目标父目录存在且没有同名文件，先同步提交身份日志（源文件的 dev/ino、大小及目标路径），再执行同文件系统原子改名，并在 Room 事务中保存视频元数据和任务状态；失败时按身份退回暂存，重启后不会接管其他同名文件。普通文件和字幕不强制解析视频。
5. 视频系统探测失败时仍保留原文件与未知元数据，实际能否播放由 libmpv 判定。启用重复检测时，按大小与首段哈希提示“可能重复”，仍保留副本。
6. 外部「打开」只在私有复制完成且取得内部视频 ID 后进入播放器；分享导入不自动播放。来源文件始终只读，不移动、不修改、不删除。

完成标记与任务记录使已复制完毕的文件不再依赖外部 URI 的临时授权。仍在复制的任务可在授权仍有效时续传；续传前逐块核对暂存前缀，来源变化或授权失效时明确失败并要求重新选择或重新分享。新暂存不在缓存清理范围；旧版 `cache/temporary` 中进行中或待重试的任务暂存也会保留。

## 3. Wi-Fi 文件服务

- 用户手动启动前台服务，每次启动重新识别 Wi-Fi、以太网及可识别的本机热点下游 IPv4，不按默认网络或“私网地址”单独推断。对合格地址分别监听固定端口 `8765`，只发布绑定成功的 `http://地址:8765/`；不监听通配地址。各监听共用同一会话、请求处理池、接收日志和传输记录。
- 从首页当前目录打开面板，启动后可按网络复制地址、查看本次传输与剩余空间；关闭面板不停止服务。浏览器资源随 APK 打包，先显示上传目标和多文件选择器；浏览目录后选择的文件保留各自目标，按选择顺序发送。网页也可下载、创建目录、重命名、移动及确认删除。
- 接收使用 1 MiB 缓冲写入 `files/web-uploads/<任务ID>.part`；完成接收和同步后入队，网页和浮层分别显示传输与保存状态。入队时 `bytesCopied` 已等于收到的文件长度，不代表保存进度：网页在手机保存中不显示百分比，只有 `COMPLETED` 才显示「已保存」。接收日志覆盖“接收完成但任务尚未入库”的进程中断；恢复时保留完整暂存并重试入队。
- 浏览器传输尚未完成就中断时，需要重新上传。已接收且暂存仍在的保存失败任务可重试保存、下载暂存；若 Worker 已确认网页暂存丢失，只能从网页重新选文件上传，原任务不再重试或提供下载入口。停止服务不取消已入队任务。
- Android 17 且 targetSdk 37 时按需请求 `ACCESS_LOCAL_NETWORK`。单个地址启动失败不影响其余可用地址；没有合格局域网或所有地址均无法监听时才报告启动失败。网络切换后需停止并重新启动以重新发现，不提供公网或 IPv6 服务。
- 服务没有登录、令牌或加密；所有能连接该地址的设备都可读写和删除文件。传输结束后手动停止，只在可信网络临时使用。

## 4. 文件操作和一致性

`FileTreeRepository` 是手机和网页的统一入口。路径受私有根目录约束，不跟随符号链接、不覆盖同名项目。列表从同一份 `lstat` 取类型与 dev/inode；首页选择、详情菜单和网页确认框保留这份快照。执行删除时在共享树锁内核对路径、类型、身份，再建日志和变更数据库。网页按字符串往返两个 64 位数，不接受只带路径的删除请求。

文件树写操作与导入最终提交共享互斥锁；修改关联视频时同步 Room 的相对路径及关联记录。操作日志和补偿处理覆盖进程中断；已移入正式位置但尚未完成入库的导入会暂时阻止相关文件树修改，避免恢复时写入旧路径。Android 实测拒绝应用创建硬链接，提交不再依赖该能力，也不会为提交再次复制大文件。日志不保证设备突然断电时目录项已经持久化。

同目录与视频同基名、可带语言后缀的字幕是独立文件，单删视频不会顺带删它们。详情页添加的副本写入 `files/subtitles/<mediaId>/`：同目录非字幕暂存名复制、刷盘成功后才在树锁内无覆盖原子发布。删除日志确认 Room 已提交后按记录 ID 清理专属目录（含整文件夹内的媒体），恢复重入同一分支；回滚保留字幕。视频与字幕都只从应用私有目录交给 libmpv。

## 5. 导出与分享

首页长按选中一个文件，在顶栏「更多」中导出或分享。导出通过系统文档选择器选择目标，以固定 1 MiB 缓冲流式写入；取消或失败时目标位置可能保留未完成文件。分享使用仅暴露 `files/media/` 的非导出 `FileProvider` 和临时读取授权；数据库和暂存不对分享方开放。

## 6. 空间与失败语义

- 入队时对已知大小检查可用空间并预留 256 MiB；大小未知时依赖写入错误反馈。容量按 1024 进制显示 `KiB`、`MiB`、`GiB` 和 `TiB`。
- 本机普通取消保留已有暂存；状态为 `CANCELED` 的原任务没有重试入口，只有可恢复的 `FAILED` 任务可重试。对本机失败或已取消任务二次确认「放弃并清理」后，才在任务锁→树锁内核对状态、归属、目标媒体记录与提交日志，按身份退回尚未入库的提交并清本任务暂存/完成标记/记录；冲突或清理失败保留记录并提示。移除已完成记录不删正式文件。
- 目标文件夹不存在或已不是文件夹时，须按原路径恢复再重试。复制前的目录检查并不证明已有暂存；提交前已复制的数据仍保留。不会自动重建目录或覆盖同名文件。两种目录检查及网页暂存丢失的历史记录按[导入恢复规则](../changes/0037-import-failure-recovery.md)识别，无需迁移。
- 清缓存不删除正式文件和待恢复的旧版暂存；容量统计包括视频、字幕及其他文件，不跟随符号链接。
- 大文件从来源到暂存及导出均为流式处理；实际可用空间、存储性能和来源 URI 授权仍是运行约束。
