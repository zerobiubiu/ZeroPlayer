# 播放引擎抽象

状态：现状文档  
影响范围：`core:playback`、`feature:player`、`tools/mpv-static`

## 1. 接口与依赖方向

[PlaybackEngine.kt](../../core/playback/src/main/java/com/privateplayer/core/playback/PlaybackEngine.kt) 暴露引擎无关的播放源、状态、音轨、字幕轨、媒体信息与错误事件。主要能力包括初始化、挂载/调整/解绑 `Surface`、加载、播放/暂停/停止、跳转、倍速、音量、音轨和字幕选择、字幕延迟及样式、画面比例、诊断与释放。

- `snapshot`、`audioTracks`、`subtitleTracks` 是 `StateFlow`；`events` 传递播放结束、失败和轨道变化。
- `PlaybackSource` 使用 Storage 层解析的应用私有文件路径。真实引擎再次按规范路径限制媒体与外挂字幕的根目录，不接受外部 URI 或网络地址。
- UI 通过 ViewModel 和共享 `PlaybackCoordinator` 借用引擎，生产引擎由协调器创建和释放；`domain` 不依赖 Compose 或 MPV。
- `diagnostics()` 返回引擎版本、`hwdec-current`、实际解码器和编解码信息；无法读取的字段为 `null`，不推断成功。

## 2. 后端与打包

`DefaultPlaybackEngineProvider.create()` 固定创建 `MpvPlaybackEngine`，不再使用模拟时钟或回退到 Mock。初始化、加载或播放失败时返回错误；不会把不可播放的媒体显示成正常播放。

`arm64-v8a` 的 `libplayer.so` 静态包含 libmpv、FFmpeg 和其他播放依赖。APK 仅支持 ARM64，不再包含其他 ABI。Kotlin JNI 包装加载随包入口库，Android 系统库及应用已有 AndroidX `.so` 仍按平台方式动态加载。安装后播放不依赖另行下载的原生库；FFmpeg 构建关闭网络协议，应用独立的网页上传服务不受影响。

- JNI 绑定基于 `jarnedemeulemeester/libmpv-android` v1.0.0 的代码，包含 UTF-16/标准 UTF-8 转换、MPV 错误回传和结束原因回调。
- 原生源码版本、下载地址与 SHA-256 固定在 `tools/mpv-static/sources.tsv`；`tools/mpv-static/build.sh` 在 Linux / WSL2 和 NDK r29 下构建。
- `MpvNativeProbe` 检查 JNI 库能否加载。加载成功只证明链接成功；不代表视频、音频或硬解已验证。
- ARM64 的可重新链接材料与来源许可须按实际分发条款保留；应用随包携带第三方许可，具体限制见 `tools/mpv-static/NOTICE.txt`。

## 3. 播放与 Surface 生命周期

`SurfaceView` 的创建、调整和销毁经 ViewModel 交给共享协调器。解绑 Surface 不等于用户关闭播放页；Activity 重建不重开视频。暂停旋转时先重配输出尺寸，再在当前位置请求重绘，保留暂停状态。用户返回关闭播放页则结束会话、释放引擎并恢复原方向；按系统主页键不是关闭播放页，可继续后台播放。

页面 ViewModel 记录该导航项是否已经提交选片请求，后续 `ON_START` 只借用当前共享会话，不按旧路由反复选片。后台自动下一文件不依赖页面存活；如果服务已经释放，则按协调器保留的最后媒体建立暂停会话。该请求标记不是独立的播放状态，实际媒体和进度仍来自 libmpv。

引擎首选 `vo=gpu`、`gpu-context=android`，尝试 `mediacodec` / `mediacodec-copy`；不支持或失败时由 MPV 回退软件解码。编码格式、渲染驱动和设备实现会影响实际结果。硬解验收必须查看实际 `hwdec-current` 和设备解码器，不能以设备宣称支持或库加载成功替代。

MPV 属性与事件驱动进度、时长、暂停、播放意图和轨道。播放器和设置订阅同一份 DataStore 字幕外观；首次装片及播放中的后续更改都交给真实引擎。普通文本轨可调字族、字形、字号、字色、背景色和位置；ASS/SSA 默认保留作者样式，显式覆盖才按纯文本重绘，关闭覆盖恢复原排版。位图字幕不重排字形。外挂与同目录字幕均可加载；选轨和延时按媒体 ID 存入 Room，不串片。

## 4. 播放器状态管理

播放器按同目录的视频文件构造顺序播放范围，支持循环、随机和自动下一文件。断点策略只有「不记录」「仅记录，从头播放」「记录并续播」；与播放历史独立，不为尚未实际播放的视频制造断点。常规、默认和系统倍速接受 0.25–8×；长按临时倍速接受 1.5–8×，松手恢复原值。引擎的系统控制与页面控制遵守相同边界。

左下按钮显示引擎实际速度。轻点扇面直接设定常规速度；长按保存当前精确值，未超过系统触摸阈值就松手不改速。主动滑动后，包括 1× 方块在内的 13 档均可试播；回到方块并松手即选 1×。滑出真实圆弧或两条直边，在抬手前就恢复原值；再进扇区可继续试播。取消、退后台和切换媒体终止旧试播，不写默认偏好。单选语义表示已提交常规档，键帽是指尖候选，上方倍速提示反映引擎实际试播。长按画面仍由独立手势控制，详见[单手倍速扇面](../changes/0038-compact-speed-fan.md)。

档位位置固定。按住时只沿相邻边界根据真实位移与时间调整抗抖距离，外弧不会吸附；手指离开或返回方块不等待计时器。键帽随指移动并避开字形，下面的扇层文字不透入键帽。临时速度经引擎确认后才绘制 HUD；紧凑横屏仅在居中会挡档位时将 HUD 平移到扇面右侧，不下移。主动试播时不再叠加非预设「已选」徽标，静止或轻点展开时仍可查精确值。

暂停时同一条目的真实位置发生变化，Media3 适配器显式通知外部控制器；仅有倍速、缓冲或普通播放时钟变化不发跳转事件。libmpv 的跳转命令提交与实际落点可能不在同一帧，不能把请求坐标当作已经抵达。

保存进度时，Room 在同一条按媒体 ID 更新断点与统计的语句中，只用引擎观测到的正时长补齐库中的非正时长。库中已有的正时长保持不变，不从播放位置猜测，也不扫描旧记录。新会话用落库时长判断是否到达 98%；引擎和库均未知时仍保留实际断点。
播放已结束且实测时长为正时，断点取完整时长；随后关闭同一会话也遵守此规则，不用较早的最后一帧时间戳覆盖片尾。

需要续播时把 `start=<秒>` 作为 `loadfile` 的逐文件选项，而不是先从零开始再在 `FILE_LOADED` 发起一次补跳。首次就绪等 libmpv 的 `PLAYBACK_RESTART` 事件；对外位置仍取真实 `time-pos`，不以数据库中拟恢复的位置冒充已经出帧。

为减轻长按倍速开始与结束时的音频链路重建，初始化时显式加载 libmpv 自带 `scaletempo2`。常速也会经过该滤镜；需要在真机复核听感、延迟与功耗，不能仅凭模拟器断言完全无卡顿。

横向手势按位移线性换算跳幅，并依据手势峰值速度把跳幅放大到 1×/2×/4×/8×/16× 档，对应 1/2/5/10/20 秒刻度，因此慢滑保持逐秒微调、快速长滑可跨越数十分钟，不再有固定的 30 秒上限。拖动时显示独立虚拟进度条；震动反馈可在设置中关闭。播放器内的手机音量键只调整媒体音量并显示百分比，不主动弹出系统音量条。

双击左、中央、右分别快退、播放/暂停、快进，随实际宽高比从三等分连续过渡到 30% / 40% / 30%。反馈和进度预览以手势层高度四分之一为目标，在安全区及顶栏下限内定位；底栏独立避开底部/横向安全区，剩余时长不带负号。画面比例只在「更多」中，旋转仍在顶栏。

MPV 技术验证由设备仪器测试承担，不再提供独立用户页面。

## 5. Android 系统媒体会话

AndroidX Media3 Common / Session 1.11.1 仅提供系统会话和控制接口，不引入 ExoPlayer 或第二套 FFmpeg。`MpvMedia3Player` 继承 `SimpleBasePlayer`，把播放、暂停、当前文件跳转、倍速和引擎音量请求转交现有 `PlaybackEngine`；不允许外部控制器设置文件或网络播放源。

`PlayerMediaSessionService` 与共享协调器管理单个会话/引擎。切到后台继续播放；明确关闭播放页则停服，不以标签切换或 Surface 消失代替关闭操作。服务负责音频焦点、前台通知和播放时的 CPU 唤醒。

会话状态来自引擎快照和当前媒体信息：媒体 ID 不匹配时不把旧进度映射给新标题，播放意图与实际播放状态分别映射。外部命令与切源共用同步门，以避免旧媒体命令作用于新文件；系统控制与界面操作仍以 libmpv 的实际结果为准。标题、时长和封面仅在已有数据可用时提供。

Media3 官方说明：[自定义 Player](https://developer.android.com/media/media3/session/player)、[后台播放服务](https://developer.android.com/media/media3/session/background-playback)。


## 6. 已验证范围与限制

早期 Android 17 / x86_64 模拟器回归曾用 H.264/AAC、双音轨、SRT 样本检查画面、暂停、跳转、轨道选择、中文字幕及旋转。该次 MediaCodec 出现 `CodecException` 后回退软解，`hwdec-current=no`；AudioTrack 初始化不是人工听音或物理硬解证据。1.1.0 的实际门禁与样片范围以[本版记录](../changes/0026-player-subtitles-and-navigation.md)为准。

导入时 Android 系统元数据探测可能漏掉容器中的字幕轨，详情页因此标注“导入探测”；实际轨道以播放器解析结果为准。ARM 真机、低版本 Android、不同编码和字幕、后台恢复、长视频及硬解仍需按 `mpv-integration-feasibility.md` 的矩阵验证。
