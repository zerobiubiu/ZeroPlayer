## 阶段 1（P1 + 2 项前置 P2）

### T-37 统一设置保存模型
- 原始问题：F-37（P1）
- 原始描述：开关即时生效，数值必须点“保存”；保存按钮禁用态像普通文字，离开页面可能丢失修改。
- 页面：设置·播放、设置·字幕
- 组件/文件：`feature/settings/.../SettingsInputs.kt`、`SettingsScreen.kt`、`SettingsViewModel.kt`、`core/datastore/.../PreferencesSettingsRepository.kt`
- 修改目标：同页所有控件采用同一种保存语义；输入完成即持久化，或全页显式保存，二者选一。
- 实施方案：
  1. 决策“即时保存”（推荐）：输入框在失焦、键盘 Done 或合法值变化后防抖保存；删除每行“保存”按钮。
  2. 非法值不写入，恢复上次值并在行内提示；保存失败通过 Snackbar 提示。
  3. 清理 `SettingsInputs.kt` 中的 `edited`/`onSave` 状态与相关文案。
- 依赖：无（阶段 1 首个任务）
- 潜在风险：连续输入导致 DataStore 写放大；需防抖（建议 300–500ms）并保证最后一次输入一定落盘。
- 验收标准：修改任意数值后直接返回并重进，值保留；输入非法值时值不落库且有提示；页面无“保存”按钮。
- 测试方法：`SettingsViewModel` 单测（防抖/非法值/失败）；Compose UI 测试（输入→返回→重进）；手测深浅色。

### T-38 打开面板时保持沉浸式
- 原始问题：F-38（P1）
- 原始描述：播放器任意底部面板弹出后系统状态栏重新出现，电池/时间压在画面上。
- 页面：播放器 → 全部面板
- 组件/文件：`feature/player/.../PlayerScreen.kt`（系统栏 `LaunchedEffect`）、`core/design/.../Dialogs.kt`（`ActionSheet`/`ModalBottomSheet`）、`PlayerScreen` 内字幕面板
- 修改目标：面板打开期间系统栏保持隐藏，关闭后仍隐藏；退出播放页恢复系统栏。
- 实施方案：
  1. 用 `OnShowListener`/sheet 生命周期回调，在面板窗口真正显示后再次 `hide(systemBars)`。
  2. 统一封装 `PlayerSystemBars` 帮助函数（进入隐藏、面板显示后隐藏、退出恢复），避免多处 `LaunchedEffect` 竞争。
  3. 校验手势导航条、状态栏在 API 26–37 的行为。
- 依赖：无（与 T-16 同批）
- 潜在风险：`ModalBottomSheet` 是独立窗口，不同 OEM 对系统栏控制不同；小窗/分屏下恢复逻辑需幂等。
- 验收标准：打开倍速/字幕/更多/队列/比例面板时无状态栏图标；关闭面板仍无；返回文件列表后状态栏恢复。
- 测试方法：实机截图（5 个面板）；`dumpsys window` 焦点确认；手测 API 26/34/37。

### T-16 面板选中语义
- 原始问题：F-16（P1）
- 原始描述：倍速/比例/音轨面板所有条目都带勾选图标，视觉上像全部已选中。
- 页面：播放器 → 倍速/画面比例/音轨/字幕面板
- 组件/文件：`core/design/.../Dialogs.kt`（`ActionSheet`、`SheetAction`）、`PlayerScreen.kt`（各面板调用）
- 修改目标：勾选只表示当前选中项；未选项无勾；当前项有明确高亮。
- 实施方案：
  1. 为 `SheetAction` 增加 `selected: Boolean = false`；`ActionSheet` 仅在 `selected` 时显示 Check，并加容器高亮（`secondaryContainer` 或同等 Token）。
  2. 更新倍速/比例/音轨/字幕面板调用，移除每行固定传 `Icons.Outlined.Check` 的写法。
  3. 为面板行补 `selectable` 语义（`Role.RadioButton`），读屏可播报选中状态。
- 依赖：无（T-37 不涉及）
- 潜在风险：`ActionSheet` 被 5+ 处调用，需逐处更新；误把普通动作（旋转/锁定）标成 selected。
- 验收标准：任一面板中勾选数量为 0 或 1，且与“（当前）”一致；TalkBack 播报“已选中/未选中”。
- 测试方法：Compose UI 测试（ActionSheet selected 渲染）；5 个面板截图；TalkBack 手测。

### T-14 建立文案资源层与 i18n 门禁
- 原始问题：F-14（P1）
- 原始描述：767 处中文硬编码、0 次 `stringResource`、无 i18n。
- 页面：全项目
- 组件/文件：各模块 `res/values/strings.xml`（需新建 feature 级资源）、`app` 资源、共享组件（`AppTopBar` 的“返回”等）
- 修改目标：用户可见文案可集中管理、可翻译；阻止新增硬编码。
- 实施方案：
  1. 按模块建 `strings.xml`（feature/home、settings、player、detail、importer、core/design 共享组件）；带占位符的文案用 `%1$s`/`%1$d`。
  2. 先迁移阶段 1/2 涉及页面（首页、设置、播放器、Wi-Fi、详情），不是一次性全量。
  3. 共享组件不接受硬编码：`AppTopBar` 的返回描述改参数或由调用方传入资源。
  4. 增加检查：Lint 自定义规则或 CI 脚本扫描 Kotlin 中的中文字面量白名单之外新增项；i18n 目标语言确认后补 `values-en`。
- 依赖：T-10（术语定稿）
- 潜在风险：模块资源不可跨模块引用；大量文案迁移产生大 diff；字符串格式化错误（`%` 转义）。
- 验收标准：目标页面 `stringResource` 覆盖；新增中文硬编码为 0；无 `String.format` 与资源占位符冲突。
- 测试方法：`lintDebug`；资源覆盖脚本；抽样页面截图对比；切换系统语言（若提供英文）。
