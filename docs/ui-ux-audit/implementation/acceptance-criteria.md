# 分阶段验收标准

验收分两层：**单项任务 DoD** 与**阶段出口门禁**。未满足任一硬性条件不得进入下一阶段。

## 1. 单项任务 DoD（所有任务通用）

1. **代码**：实现符合 `task-breakdown.md` 的修改目标；不扩大范围；不引入未在计划中的新组件/页面。
2. **编译**：`:app:assembleDebug` 通过；涉及 Token/主题的改动同时通过 `:app:lintDebug`（0 error）。
3. **测试**：新增/更新的单测或 UI 测试通过；受影响的既有测试全部通过。
4. **文案**：新增用户可见文案进入资源（阶段 1 之后）；无新增硬编码；术语符合术语表。
5. **截图**：涉及页面在浅色、深色（适用时）、1.3 倍字号下各一张；播放器/大屏按矩阵补拍。
6. **无障碍**：新增/修改的交互控件有可访问名称；触控目标 ≥48dp；开关/选中语义正确。
7. **回归**：影响的调用方全部验证；文件中写明影响范围与手工验证步骤。
8. **文档**：在 `docs/changes/` 记录改动（执行阶段）；更新相关现状文档；不修改审计报告原文。

## 6. 阶段 4：完整回归与交付

### 6.1 必过项

- [ ] 编译、Lint、全量 JVM 单测、相关仪器化测试全部通过。
- [ ] `validation-matrix.md` 的最低设备矩阵（D1–D4）完成；大屏/折叠屏（如确认支持）完成。
- [ ] 字体 1.0/1.3/2.0、浅/深色、横竖屏截图齐全，无截断/重叠。
- [ ] 硬件键盘焦点顺序可用（Tab/Enter/Esc），焦点可见。
- [ ] SAF：单/多文件导入、取消、重试、导出、分享、外部打开全部通过；原始文件哈希不变。
- [ ] 通知/锁屏：播放/暂停/上下集/关闭后消失；无残留会话。
- [ ] 播放器：播放、切轨、字幕、手势、后台、横屏各 5 分钟无异常。

- [ ] 无 P0/P1 新增问题；既有 P1 全部关闭或书面接受。

### 6.2 交付物

1. 代码变更与测试（执行阶段）。
2. `docs/ui-ux-audit/implementation/evidence/` 下的 before/after 截图与日志索引。
3. 更新的 `docs/changes/` 变更记录、`docs/architecture/feature-status.md`、设计系统文档。
4. `findings.md` 状态列更新（实施阶段回填，不改写原始描述）。
5. 回归报告：覆盖设备、用例、结果、残余风险。

## 7. 阻塞与放行规则

- 任一硬依赖未完成：后续任务可做设计/测试准备，不合并代码。
- 出现与审计无关的新缺陷：单独记录，不夹带进本次整改，除非阻断验收。
- 设备/环境不可得（如无真机）：该用例标记“未验证”，不得以模拟器结果替代真机结论；需在交付报告中列出残余风险。
- 文案术语/i18n 语言未确认：可先完成不依赖术语的组件任务（T-16/T-38 等），文案任务保持待定。
