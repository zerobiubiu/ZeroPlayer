## 三、整体评价

工程底子好于同类个人项目：Material 3 组件使用规范、深浅色对比度全部达到 AA、空/错/载状态齐全、危险操作有确认、文件名校验有内联错误、播放器手势与控件的手势区域已经分离。桌面级信息架构（文件树 + 设置二级页）清晰，文案整体克制，没有营销腔。

问题集中在三类：

1. **信息与操作的组织**：设置分组按“页面”而非“用户任务”切分；详情页与首页职责重叠且缺少文件操作；播放器入口图标与实际结果不一致。
2. **文案的一致性与技术泄漏**：同一设置在三个位置三种叫法；关于页、Wi-Fi 面板、详情页大量暴露 `libmpv`、`libplayer.so`、`assets/...`、`bps`、`导入探测` 等实现细节；767 处中文字面量、0 个 `stringResource`，没有可维护的文案层。
3. **组件与视觉的一致性**：两套顶栏、两套删除对话框、4 个死组件、播放器完全绕开设计 Token；筛选/选中语义被“每行一个勾”削弱；面板内每个条目都像已选中。

## 四、八个维度评价

| 维度 | 评价 | 主要问题 |
|---|---|---|
| UX Writing | 语句普遍简短、动词明确；一致性与技术化是短板 | 术语三套叫法、内部路径/实现细节外泄、安全提示被埋没、无 i18n |
| Visual Hierarchy | 主次关系总体成立，标题不过度 | 详情页数据重复形成双重点、面板勾选图标误导、单控件页面层级过度 |
| Information Architecture | 一级结构简单，二级职责有交叉 | 设置分组混合配置/信息/动作、旋转入口错位、播放列表名不副实、详情缺文件操作 |
| Layout Design | 间距与对齐稳定，深浅色表现一致 | 两行列表浪费高度、面包屑过高、信息表无分组、数值行过高 |
| Information Density | 列表与设置页密度不均 | 文件夹行无有效副信息、范围提示常驻、播放器面板档位平铺 |
| Component Design | M3 组件使用得当，但复用不彻底 | 两套顶栏/对话框、死组件、触控目标不足、令牌绕过 |
| Interaction Design | 加载/空/错状态完整，危险操作有确认 | 保存模型不一致、面板破坏沉浸式、错误恢复路径缺失、无多选批量 |
| Accessibility | 对比度与语义描述优于平均，触控与开关语义需修 | 对比度全部 ≥4.5:1（通过）、图标均有描述；开关双目标、触控 <48dp、键盘未验证 |

## 六、最值得优先处理的事项

1. **先修交互一致性**（F-37、F-38、F-16）：统一“即时生效”模型，修正面板语义与沉浸式状态栏，改动小、收益立竿见影。
2. **再修入口与信息架构**（F-19、F-20、F-21、F-18）：旋转/比例归位，播放列表名副其实，详情页补齐文件操作。
3. **然后建立文案层**（F-14、F-10、F-09）：把文案集中到 `strings.xml`，统一术语表，安全提示升级为警示块。
4. **最后做组件收敛**（F-30、F-32、F-31、F-34）：一套顶栏/对话框、删除死组件、播放器接入 Token。
